# v0.15 Audit Trail

## Purpose

Record an immutable audit trail for sensitive actions, required by `PRODUCT-REQUIREMENTS` (audit trail, P0) and `SECURITY-COMPLIANCE` §8 (record approving user, decision and timestamp for every publication decision).

## Data model

New append-only table `audit_events` (migration `20260929195120_AddAuditEvents`):

- `Action` — stable action id (`video.approved`, `video.rejected`)
- `Actor` — reviewer/user identity
- `WorkspaceId` / `VideoProjectId` — optional scoping (no FK, so audit survives entity deletion)
- `DetailsJson` — structured details
- `CreatedAtUtc` — timestamp

Audit records are never mutated. There is no update or delete endpoint.

## Service

`IAuditService.Record(...)` appends an audit entry to the current unit of work. The caller persists it inside its own transaction so the audit entry is atomic with the action it describes.

## Integration

The `ApprovalController` records `video.approved` on approval (with render asset id and notes) and `video.rejected` on rejection (with notes), scoped to the workspace and project.

## Endpoint

`GET /api/v1/video-projects/{id}/audit` — returns the project's audit events, newest first.

## Verification

Backend coverage: audit event written on approve and on reject; read endpoint returns project-scoped events newest-first and 404 for missing project. CI e2e asserts a `video.approved` audit event exists after approval, plus the new migration and `audit_events` table.
