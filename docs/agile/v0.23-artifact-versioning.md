# v0.23 Artifact Versioning

## Purpose

Version production artifacts so regenerating one appends a new version instead of silently overwriting the previous one (DATA-MODEL §3: "Never silently overwrite a meaningful AI-generated artifact").

## Model

`ProductionArtifact.Version` (int, 1-based, default 1, migration `20260929205935_AddArtifactVersion`). Indexed by `(VideoProjectId, Type, Version)`.

## Behaviour

- The production worker's `AddArtifactAsync` computes `Version = max(existing for project+type) + 1`, so each generated artifact is a new version.
- The manual scene-plan endpoint uses the shared `db.NextVersionAsync(...)` helper for the same guarantee.
- Artifacts remain append-only; the versioned history is preserved and exposed.

## API

`GET /api/v1/video-projects/{id}/artifacts` now returns `version` for each artifact.

## Verification

Backend coverage: `NextVersionAsync` increments per project+type and restarts per type; the artifacts endpoint exposes the version. CI e2e asserts every artifact has `version >= 1`.
