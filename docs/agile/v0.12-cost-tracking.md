# v0.12 Cost Tracking

## Production-loop position

Cross-cutting. Every provider/rendering step that has a measurable cost records one cost row while the production worker runs.

This story implements MVP Phase 5 (provider usage tracking, cost per video) and backlog story US-022.

## Data model

New table `production_costs` (migration `20260929182331_AddProductionCosts`). One row per stage:

- `VideoProjectId`
- `Stage` — the production stage (`Voice`, `Visual`, `MusicSfx`, `Captions`, `Thumbnail`, `Render`)
- `Provider` — the provider asset id / provider that incurred the cost
- `Units` — billable units (seconds, scenes, candidates, per-video)
- `UnitCostUsd` — cost per unit
- `TotalCostUsd` — `Units * UnitCostUsd`

Indexed by `(VideoProjectId, Stage)`.

## Worker behaviour

`VideoProductionWorker` records a cost row after each billable stage using a default per-stage rate table (`CostRates`). Real providers should record their own metered costs; the default rates keep the cost-per-video calculation populated for the placeholder providers in the MVP.

## Endpoint

`GET /api/v1/video-projects/{id}/costs`

Returns:

- `totalCostUsd` — total cost for the project
- `byStage` — total cost grouped by stage, highest first
- `lineItems` — every recorded cost row in chronological order

## Verification

Backend regression coverage includes missing project, empty costs, aggregation and grouping by stage, and project scoping. The end-to-end CI flow asserts that a completed project has a positive total cost and a `Render` stage cost.
