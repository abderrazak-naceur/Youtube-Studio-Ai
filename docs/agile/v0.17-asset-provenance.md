# v0.17 Asset Manifest & Rights/Provenance

## Purpose

Attach provenance and rights metadata to every generated media asset, per `VIDEO-PRODUCTION-PIPELINE` (asset manifest fields) and `SECURITY-COMPLIANCE` §4. Unknown rights must never be treated as safe.

## Model

`RightsStatus` enum: `Unknown`, `Licensed`, `Owned`, `Generated`, `PublicDomain`. `Unknown` is the default and is treated as unsafe.

`AssetProvenance` record carries: provider, model/tool, rights status, content hash (SHA-256), prompt reference, generated-at timestamp — mirroring the manifest fields from the production pipeline doc.

## Worker

Voice, Visual, Music/SFX and Thumbnail artifacts now embed a `provenance` object in their `MetadataJson`. Placeholder providers generate synthetic content, so the rights status is `Generated`; real provider adapters should supply their own licensing metadata. No migration is required (the existing `MetadataJson` column is reused).

## QA gate

`QaRequest` gains `AllAssetsHaveKnownRights` (default `true`). `DefaultQaProvider` blocks the video when any asset has unknown rights/provenance status, so unknown-rights media cannot pass the quality gate.

## Verification

Backend coverage: QA fails when `AllAssetsHaveKnownRights` is false. CI e2e asserts the Voice artifact's `MetadataJson` carries a `provenance` object with a rights status and a non-empty content hash.
