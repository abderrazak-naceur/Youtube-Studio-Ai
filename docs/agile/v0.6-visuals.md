# v0.6 Visuals

## Scope

Advance the production journey from **Scene Plan → Visuals** using the existing replaceable `IVisualProvider` boundary.

## Endpoint

`POST /api/v1/video-projects/{id}/visuals`

The endpoint:

1. Requires an existing video project in `Planned` state.
2. Loads the latest persisted `ScenePlan` production artifact.
3. Validates that the persisted plan contains usable scene numbers, durations, and visual directions.
4. Calls `IVisualProvider` once per scene with the scene's visual direction and duration.
5. Validates every provider result before changing project state.
6. Persists one `ProductionArtifact` of type `Visual` per scene, including the scene number, media type, and duration in metadata.
7. Changes the project status to `Producing` only after all generated artifacts are ready to save.

If any provider response is invalid, the request returns `502 Bad Gateway` and does not persist partial visual artifacts or advance the project state.

## Provider boundary

The API depends only on `IVisualProvider`; the current placeholder implementation remains replaceable. Provider credentials are not part of the endpoint contract and must remain server-side/configurable.

## Verification

`VisualsControllerTests` covers:

- missing project;
- invalid project state;
- missing persisted scene plan;
- successful per-scene provider calls and artifact persistence;
- invalid provider output with no partial persistence.
