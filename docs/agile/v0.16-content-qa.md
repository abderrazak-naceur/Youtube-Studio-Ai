# v0.16 Real Content & Editorial QA

## Purpose

Replace the placeholder QA (which always passed) with a QA provider that runs real technical and editorial checks, per backlog US-019/US-020, `QA-AGENT` and `VIDEO-PRODUCTION-PIPELINE`. This gives substance to the human quality gate: a failing QA blocks approval.

## Behaviour

`DefaultQaProvider` evaluates the computable gates that do not require decoding media:

**Technical gates**
- rendered video asset present
- render duration > 0
- narration duration > 0
- captions present

**Editorial gates**
- title present
- scene plan has scenes
- thumbnail present
- publish metadata present
- script long enough to be a coherent narrative (≥ 20 words)
- originality heuristic: no single word exceeds 35% of the meaningful words (flags templated/spam scripts)

Any blocking failure returns `Passed = false` with a list of findings. The worker already fails the job when QA does not pass, and the approval gate independently re-checks the persisted `Passed` flag.

## Contract change

`QaRequest` was extended with production context (`SceneCount`, `VoiceDurationSeconds`, `RenderDurationSeconds`, `HasCaptions`, `HasThumbnail`, `HasMetadata`) so QA can assess coherence and completeness. `QaResult` is unchanged (`Passed`, `Findings`), so the approval gate's `Passed` check is preserved.

## Verification

Backend coverage: pass case plus failures for missing render, missing captions, missing thumbnail/metadata, too-short script, repetitive script and empty scene plan. The existing end-to-end flow still produces a passing QA for the placeholder pipeline (script length and asset presence satisfy the gates).
