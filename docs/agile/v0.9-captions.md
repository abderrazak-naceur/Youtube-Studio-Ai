# v0.9 Captions

## Production-loop position

`Idea/Prompt → Research → Script → Scene Plan → Visuals → Voice → Music/SFX → Captions`

This story adds the timed-caption generation boundary needed by the later Edit/Render stage.

## Endpoint

`POST /api/v1/video-projects/{id}/captions`

The endpoint is intentionally provider-neutral and resolves `ICaptionProvider` from dependency injection.

## Preconditions

- The video project exists.
- The project is `Producing`.
- A persisted non-empty `Script` artifact exists.
- A persisted `Voice` artifact exists with a non-empty provider asset id and valid `durationSeconds` metadata.
- A completed `MusicSfx` artifact exists with a non-empty provider asset id.

## Provider contract

`ICaptionProvider.GenerateCaptionsAsync` receives the persisted script and returns:

- a provider asset id;
- one or more `CaptionEntry` values with start/end seconds and text.

The API validates that entries are finite, ordered, non-overlapping, non-empty, start at or after zero, and end within the persisted voice duration. Invalid provider output is rejected with `502 Bad Gateway` before persistence.

## Persistence

A valid result is persisted as one `ProductionArtifact` with type `Captions`. Timed entries and production duration are stored in `MetadataJson`, leaving the existing artifact model unchanged and avoiding a migration for this increment.

Provider credentials remain outside the API contract and are supplied only by the provider implementation/configuration layer.
