# v0.39 Object Storage Abstraction

## Purpose

Provide a portable object-storage boundary for raw and generated media (SYSTEM-ARCHITECTURE §5: object storage for audio/video/images/subtitles; PostgreSQL stores references only).

## Design

`IObjectStorage`:
- `PutAsync(key, content, contentType)`
- `GetAsync(key)` → bytes or null
- `ExistsAsync(key)`

`LocalFileObjectStorage` is the MVP implementation over the local filesystem, rooted at `ObjectStorage:RootPath` (default: a temp subfolder). Keys are normalized and confined to the root — traversal keys (`../…`) are rejected. A cloud backend (S3 / DigitalOcean Spaces) can replace it later without changing callers.

## Verification

Backend coverage: put/get round-trips content; `Exists` reflects stored objects; `Get` returns null for a missing key; path-traversal keys are rejected.
