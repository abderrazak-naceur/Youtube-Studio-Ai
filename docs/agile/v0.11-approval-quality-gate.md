# v0.11 Approval / Human Quality Gate

## Production-loop position

`… → Render → QA → Awaiting Approval → (Approve) Completed | (Reject) Rejected`

This story implements MVP Phase 4's non-negotiable rule and backlog story US-021: no final video can bypass the required critical checks, and final export requires an explicit human decision.

## Behaviour change

The automated production worker no longer moves a project directly to `Completed`. After automated QA passes, the project stops at the new `AwaitingApproval` state. Only an explicit approval decision moves a project to `Completed` (final export). A rejection moves it to `Rejected`.

New `VideoProjectStatus` values: `AwaitingApproval`, `Rejected`. Both persist through the existing string conversion, so no migration is required.

## Endpoints

- `POST /api/v1/video-projects/{id}/approve`
- `POST /api/v1/video-projects/{id}/reject`

Both accept `{ "reviewer": string, "notes": string | null }`.

## Approval preconditions

- The video project exists.
- The project is `AwaitingApproval`.
- A reviewer identity is provided.
- A `Render` artifact with a provider asset id exists.
- The persisted `Qa` artifact recorded a passing result (`Passed = true`).

If QA did not pass or the render is missing, approval is blocked with `409 Conflict`. This is the critical gate: a project can never reach `Completed` without a passing QA artifact and an explicit approval.

## Rejection preconditions

- The video project exists and is `AwaitingApproval`.
- A reviewer identity and rejection notes are provided (the failure reason must be recorded).

## Persistence

Every decision is persisted as one `ProductionArtifact` of type `Approval`. The metadata records the decision (`approved`/`rejected`), the reviewer and the decision timestamp; reviewer notes are stored in `Content`. Approved artifacts carry the render provider asset id so the exported asset is traceable.

## Verification

Backend regression coverage includes missing project, missing reviewer, wrong state, blocked approval without render, blocked approval when QA failed, successful approval, rejection notes requirement and successful rejection. The end-to-end CI flow now waits for `AwaitingApproval`, calls `approve`, and asserts the project reaches `Completed` with a persisted `Approval` artifact.
