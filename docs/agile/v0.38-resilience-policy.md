# v0.38 Resilience Policy

## Purpose

Retry transient provider failures with backoff and per-attempt timeouts (SYSTEM-ARCHITECTURE §8: retry transient failures, use timeouts; never retry non-idempotent publishing blindly).

## Design

`ResiliencePolicy.ExecuteAsync(operation, isTransient, options, ct, delay)`:
- runs `operation` up to `MaxAttempts` times;
- each attempt has a per-attempt timeout (linked cancellation);
- retries only when `isTransient` returns true (a per-attempt timeout counts as transient);
- backs off exponentially (`BaseDelay × 2^(attempt-1)`);
- never retries caller cancellation;
- the delay function is injectable so tests run without real waiting.

## Applied to the HTTP script provider

`HttpScriptProvider` now wraps its LLM call in the policy. Network errors and 5xx responses are transient (retried); 4xx are not. After retries are exhausted it still falls back to the placeholder, so production never breaks.

## Verification

Backend coverage: success on first attempt; retries transient then succeeds; does not retry non-transient; throws last exception after exhausting attempts; caller cancellation not retried.
