# v0.27 Domain Events

## Purpose

Emit an append-only domain event stream to support async workflows, auditability and learning (DATA-MODEL §4, EVENT-MODEL).

## Model

`DomainEvent` (table `domain_events`, migration `20260929212141_AddDomainEvents`) with the event envelope: `Type`, `WorkspaceId`, `AggregateId`, `OccurredAtUtc`, `SchemaVersion`, `Payload` (JSON). Immutable, append-only, no FKs (events survive aggregate deletion). Indexed by workspace, aggregate and type.

## Publisher

`IDomainEventPublisher.Publish(type, workspaceId, aggregateId, payload)` appends an event to the current unit of work, so the event is atomic with the state change.

## Emitted events

- `opportunity.created` — when an opportunity is created.
- `video.approved` / `video.rejected` — at the human quality gate (alongside the audit record).
- `quality_gate.failed` — when automated QA fails in the production worker.

## API

`GET /api/v1/workspaces/{workspaceId}/events?type=` — workspace-scoped, newest first, optional type filter (max 200).

## Verification

Backend coverage: publisher appends on save; endpoint returns workspace events with type filter; non-member forbidden. CI e2e asserts a `video.approved` event on the workspace stream after approval; new migration and `domain_events` table verified.
