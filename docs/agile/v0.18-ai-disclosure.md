# v0.18 AI Disclosure Workflow

## Purpose

Support the AI disclosure requirement for synthetic/altered content, per `PRODUCT-REQUIREMENTS` product rules and `SECURITY-COMPLIANCE` §5. Because the MVP pipeline generates synthetic media, every project requires an AI disclosure by default, and the human quality gate cannot be passed until the reviewer acknowledges it.

## Model

`VideoProject.RequiresAiDisclosure` (bool, default `true`, migration `20260929200054_AddAiDisclosureFlag`). Real-footage projects could set this to `false` in future; the MVP defaults to requiring disclosure.

## Approval gate

`ApprovalDecisionRequest` gains `AiDisclosureAcknowledged` (default `false`). On approval:

- if the project `RequiresAiDisclosure` and the request does not acknowledge it, approval is blocked with `409 Conflict`;
- when acknowledged, the decision is recorded on the `Approval` artifact (`aiDisclosureAcknowledged`, `requiresAiDisclosure`) and in the audit event.

This composes with the existing gates: a video reaches `Completed` only when QA passed, a render exists, rights are known, and the AI disclosure is acknowledged.

## Verification

Backend coverage: approval blocked when disclosure not acknowledged; approval succeeds when acknowledged. CI e2e asserts that approval without acknowledgement returns `409` and that acknowledged approval reaches `Completed`, plus the new migration.
