# v0.14 Metadata

## Production-loop position

`… → Captions → Thumbnail → Metadata → Render`

This story adds publish-ready metadata generation, a mandatory MVP artifact (`PRODUCT-REQUIREMENTS` P0, Definition of Done "complete metadata").

## Endpoint

`POST /api/v1/video-projects/{id}/metadata`

Provider-neutral; resolves `IMetadataProvider` from dependency injection.

## Preconditions

- The video project exists.
- The project is `Producing`.
- A persisted non-empty `Script` artifact exists.

## Provider contract

`IMetadataProvider.GenerateMetadataAsync` receives the project title, script and language, and returns a SEO-oriented `title`, `description`, `tags`, `category` and `language`. Incomplete output (empty title or description) is rejected with `502 Bad Gateway` before persistence.

## Persistence

A valid result is persisted as one `ProductionArtifact` of type `Metadata`. The SEO title is stored on `Content`; the full metadata object (title, description, tags, category, language) is stored in `MetadataJson`. The enum addition persists through the existing string conversion, so no migration is required.

## Verification

Backend regression coverage: missing project, invalid state, missing script, request propagation, successful persistence and incomplete provider output. The production worker generates metadata between Thumbnail and Rendering. CI e2e asserts a `Metadata` artifact and an artifact count of at least 12.
