# v0.21 Resumable Production

## Purpose

Make production resumable and avoid duplicating paid external operations on retry (backlog US-002 "resume from the last completed stage", SYSTEM-ARCHITECTURE §8 reliability, VIDEO-WORKFLOW idempotency).

## Behaviour

`VideoProductionWorker` no longer rebuilds everything from scratch when a job restarts:

- **Research, Script, Scene Plan** are resume-safe: if an artifact for the stage already exists, the worker reconstructs the result from it (summary/sources, title/script, scenes) instead of calling the provider again.
- `ProductionJob.LastCompletedStage` is updated after each major stage (`Research`, `Script`, `ScenePlan`, `Render`, `Qa`), giving an observable resume point.

This directly protects against re-charging providers for stages that already succeeded before a failure.

## Notes

The reuse logic reads the latest persisted artifact per stage. The later producing stages (voice/visuals/etc.) still regenerate on a fresh run; extending resume to those is a follow-up once real, metered providers are integrated (the idempotency-key work in v0.22 lays the groundwork).

## Verification

All backend tests pass. The end-to-end CI flow asserts that a completed project's job reports `lastCompletedStage = "Qa"`.
