# v0.10 Thumbnails

## Production-loop position

`Idea/Prompt → Research → Script → Scene Plan → Visuals → Voice → Music/SFX → Captions → Thumbnails`

This story adds the thumbnail-candidate generation boundary required by Phase 3 of the MVP plan (thumbnail pipeline) and backlog story US-018.

## Endpoint

`POST /api/v1/video-projects/{id}/thumbnails`

The endpoint is provider-neutral and resolves `IThumbnailProvider` from dependency injection.

## Preconditions

- The video project exists.
- The project is `Producing`.
- A persisted non-empty `Script` artifact exists.

## Provider contract

`IThumbnailProvider.GenerateThumbnailsAsync` receives the project title, persisted script and a requested candidate count, and returns one or more `ThumbnailCandidate` values. Each candidate carries a provider asset id, a headline and a media type.

The API validates that every candidate has a non-empty provider asset id, headline and media type. Empty provider output is rejected with `502 Bad Gateway` before persistence.

## Persistence

A valid result is persisted as one `ProductionArtifact` with type `Thumbnail`. The primary candidate's provider asset id is stored on `ProviderAssetId`, and the full candidate list is stored in `MetadataJson`. The enum addition is persisted through the existing string conversion, so no migration is required for this increment.

The project remains in `Producing` so later stages can consume the accumulated assets.

Provider credentials remain outside the API contract and are supplied only by the provider implementation/configuration layer.

## Verification

Backend regression coverage includes missing projects, invalid state, missing script, provider request propagation, successful candidate persistence and invalid provider output without partial persistence. The end-to-end production worker generates thumbnails between Captions and Rendering and persists a `Thumbnail` artifact.
