# v0.22 Job Cancel & Idempotent Enqueue

## Purpose

Add job cancellation and idempotent enqueue (API-ENDPOINTS `POST /jobs/{id}/cancel`, API-DESIGN idempotency for expensive mutations, SYSTEM-ARCHITECTURE job model).

## Cancel

`POST /api/v1/video-projects/{id}/cancel` (authenticated, workspace member):
- if there is an active job (`Queued` or `Running`), it is set to `Cancelled` and the project moves to `Cancelled`;
- if there is no active job, returns `409 Conflict`.

New states: `ProductionJobStatus.Cancelled`, `VideoProjectStatus.Cancelled` (both persist via string conversion).

Note: cancellation is guaranteed for queued jobs; for a job already running in the worker it is best-effort (the worker finishes the current in-memory pass). Cooperative mid-run cancellation is a follow-up.

## Idempotent enqueue

`ProductionJob.IdempotencyKey` (nullable, migration `20260929205426_AddJobIdempotencyKey`). `Start` reads an optional `Idempotency-Key` header and passes it to `EnqueueAsync`. A retried enqueue with the same key returns the existing job instead of creating a duplicate. The existing active-job guard still prevents two concurrent jobs per project.

## Verification

Backend coverage: cancel marks job + project cancelled; cancel with no active job returns conflict; enqueue with the same idempotency key returns the same job; enqueue without a key does not duplicate an active job.
